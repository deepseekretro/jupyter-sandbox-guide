# 05 — 持久化与迁移

**这一节决定你的工作会不会白做。** 沙盒随时可能消失，必须知道什么能活下来。

---

## 残酷的真相

### 容器生命周期

```
创建容器
   ↓
你干活（几小时 / 几天 / 几周）
   ↓
容器停止  ← 数据可能丢
   ↓
容器重启  ← 数据可能丢
   ↓
容器销毁  ← 全丢
```

**唯一可靠的是挂载的持久卷。**

### 实测：什么会丢

| 路径 | 容器重启 | 容器重建 |
|---|---|---|
| `/`（overlay） | 保留 | ❌ **全丢** |
| `/tmp` | 保留（如果和 `/` 同分区） | ❌ 全丢 |
| `/root` | 保留 | ❌ 全丢 |
| `/opt/*` | 保留 | ❌ 全丢 |
| `/dev/shm` | ❌ 丢（tmpfs） | ❌ 丢 |
| `/home/jovyan/JupyterLabRoot` | ✅ **保留** | ✅ **保留** |

**关键：`/home/jovyan/JupyterLabRoot` 是宿主 bind mount，是唯一的持久位置。**

## 找到你的持久卷

### 方法 1：看挂载表

```bash
cat /proc/mounts | grep -vE "^(proc|sysfs|devpts|tmpfs|cgroup|mqueue|shm|overlay / )"
```

找 `ext4` / `xfs` 且不是 overlay 的挂载点：

```
/dev/root /etc/resolv.conf        ext4  ← 只读配置
/dev/root /home/jovyan/JupyterLabRoot  ext4  ← ★ 这是持久卷
```

### 方法 2：找非 overlay 目录

```bash
# 所有挂载点及其类型
findmnt -t ext4,xfs,btrfs -o TARGET,SOURCE,FSTYPE
```

### 方法 3：看 Jupyter 的 home

```bash
echo $HOME                    # /home/jovyan（通常）
ls -la /home/jovyan/          # 有没有子目录是挂载的
df -h /home/jovyan/*          # 哪个分区和 / 不同
```

**判断标准**：`df` 显示的设备与 `/` 不同 → 是独立挂载 → 大概率持久。

## 备份策略

### 原则

1. **产物要小**：只备份结果，不备份中间文件
2. **多副本**：本地 + 云盘 + 另一台机器
3. **可校验**：每个文件带 md5/sha256
4. **可复现**：不只是二进制，还要源码 + 构建脚本

### 最小备份清单

```
必存：
├── 源代码 / 补丁
├── 构建脚本（能一键重建）
├── 产物（二进制 / 数据）
├── 校验和（SHA256SUMS）
└── 说明文档（README：怎么用）

不必存：
├── 编译中间文件（.o / target/）
├── 包管理器缓存
├── 下载的原始安装包（能从官方再下）
└── /tmp 下的临时文件
```

### 打包脚本

```bash
#!/bin/bash
set -e
OUT=/home/jovyan/JupyterLabRoot/backup-$(date +%Y%m%d-%H%M).tar.gz

tar czf "$OUT" \
  --exclude='*.o' --exclude='*.a' \
  --exclude='target/' --exclude='node_modules/' \
  --exclude='.git/' \
  -C /root myproject

cd "$(dirname "$OUT")"
sha256sum "$(basename "$OUT")" > "$(basename "$OUT").sha256"
echo "✔ $OUT"
ls -lh "$OUT"
```

## 传输出去的几种方式

### 方式 1：rclone → 云盘（推荐）

**最省心**，支持断点续传、多后端（OneDrive/Google Drive/S3/SFTP）。

```bash
# 装
curl https://rclone.org/install.sh | bash

# 配置（交互式，生成 ~/.config/rclone/rclone.conf）
rclone config

# 上传
rclone copyto local.tar.gz remote:bucket/local.tar.gz

# 校验（rclone 自带 hash 校验）
rclone check local.tar.gz remote:bucket/ --download
```

**优点**：加密传输、断点续传、校验、支持几十种后端。

### 方式 2：SSH 直传

如果沙盒能 SSH 出去：

```bash
# 推
cat file.tar.gz | ssh user@host 'cat > /path/file.tar.gz'

# 拉
ssh user@host 'cat /path/file.tar.gz' > local.tar.gz

# 校验
sha256sum file.tar.gz
ssh user@host 'sha256sum /path/file.tar.gz'
```

**缺点**：无进度、无断点续传、占终端。

### 方式 3：scp / rsync（如果对端支持）

```bash
scp file.tar.gz user@host:/path/
rsync -avP file.tar.gz user@host:/path/
```

> ⚠️ dropbear 没有 sftp-server，`scp`/`sftp` 用不了。只有 OpenSSH 服务端才行。

### 方式 4：HTTP 上传

```bash
# 传到临时文件服务（注意数据敏感性！）
curl -F "file=@file.tar.gz" https://transfer.sh/upload

# 或自己起个服务
python3 -m http.server 8000
```

### 方式 5：Jupyter 界面下载

直接在文件浏览器里右键 Download。适合小文件（< 几百 MB）。

## 迁移到另一台机器

### 完整迁移清单

```bash
# 1. 生成环境快照
echo "=== 系统 ===" > env.txt
cat /etc/os-release >> env.txt
uname -a >> env.txt
echo "=== 已装包 ===" >> env.txt
dpkg -l | awk '/^ii/{print $2, $3}' >> env.txt
echo "=== 关键配置 ===" >> env.txt
cat /etc/apt/sources.list >> env.txt

# 2. 打包项目
tar czf project.tar.gz -C /root project/

# 3. 传出去
rclone copyto project.tar.gz drive:backup/
rclone copyto env.txt drive:backup/

# 4. 在新机器上还原
rclone copy drive:backup/project.tar.gz .
tar xzf project.tar.gz -C /root
diff env.txt <(cat /etc/os-release; uname -a)   # 对比差异
```

### 跨架构迁移

从 x86 到 ARM（或反之）：

```bash
# proot 的 -q 参数能用 QEMU 模拟
proot -q qemu-aarch64-static \
  --rootfs=/path/to/arm-rootfs \
  -0 -b /proc -b /dev /bin/bash
```

**性能损失巨大**（10-20x），只适合跑轻量验证。

真正的跨架构迁移：**在目标架构上重新编译**。

## 开机自愈

容器重启后，手工启动的服务全没了。需要自愈脚本。

### 自检测模式

```bash
#!/bin/bash
# /root/boot-agent.sh —— 由 cron 或登录时触发

check_and_start() {
    local name="$1" cmd="$2" probe="$3"
    if ! eval "$probe" >/dev/null 2>&1; then
        echo "[$(date +%T)] $name 未运行，启动中..."
        eval "$cmd"
        sleep 2
        if eval "$probe" >/dev/null 2>&1; then
            echo "[$(date +%T)] $name ✔ 已启动"
        else
            echo "[$(date +%T)] $name ✗ 启动失败"
        fi
    fi
}

# SSH 服务
check_and_start "dropbear" \
  "/opt/dropbear/sbin/dropbear -p 22 -r /etc/dropbear/dropbear_ed25519_host_key" \
  "pgrep -f dropbear"
```

### 用 cron 周期检查

```bash
# 每 2 分钟检查一次
(crontab -l 2>/dev/null; echo "*/2 * * * * /root/boot-agent.sh >/tmp/boot.log 2>&1") | crontab -
```

**cron 在 proot 里能跑**（不需要 systemd）：

```bash
apt-get install -y cron
cron           # 启动
# 或
service cron start
```

### 如果连 cron 都没有

用 `while` 循环守护：

```bash
setsid nohup bash -c '
while :; do
  /root/boot-agent.sh
  sleep 120
done' > /tmp/daemon.log 2>&1 < /dev/null &
```

## 反模式：这些做法会让你丢东西

### ❌ 只备份二进制

```
备份了 app 二进制，没备份源码
→ 二进制出问题没法修
→ 换架构没法重编
```

**正确**：源码 + 构建脚本 + 二进制 + 校验和。

### ❌ 把重要东西放 /tmp

```bash
cp important.tar.gz /tmp/     # ❌ 容器重建就没了
```

### ❌ 假设 `/tmp` 是 tmpfs

实测过：`/tmp` 和 `/` 可能同为 overlay（135G），所以能放大文件。**但容器重建照样丢。** 不要因为"现在能用"就当真。

### ❌ 信任 cgroup 的 max

`cgroup memory.max` 显示 `max` 但实际有硬限的情况真实存在。**实测才准。**

### ❌ 服务端不开自愈

手工 `nohup` 起的服务，容器重启后全死。**必须有 boot-agent。**

### ❌ 备份不验证

```
"我备份了" → 其实 tar 不完整 / 文件损坏 / 少了关键目录
```

**正确**：备份后**立即解包验证**，能真的编译/运行才算备份成功。

> 血泪教训：曾备份了 rclone 源码包，解包后编译失败 ——
> 因为模板文件是旧版本（365 行 vs 源码 394 行）。
> **只备份不验证 = 假备份。**

## 校验和规范

```bash
# 生成
sha256sum *.tar.gz > SHA256SUMS

# 校验（不匹配会报错）
sha256sum -c SHA256SUMS

# 上传后云端再校验
rclone cat remotes:path/SHA256SUMS
rclone check remotes:path . --include "*.tar.gz"
```

**每次传输都校验。** md5 够快，sha256 更安全。

## 小结

| 项 | 要点 |
|---|---|
| 唯一持久 | 宿主 bind mount（通常 `/home/jovyan/JupyterLabRoot`） |
| 其余全丢 | `/`、`/tmp`、`/root`、`/opt`（容器重建时） |
| 备份内容 | 源码 + 脚本 + 产物 + 校验和 + 文档 |
| 传输首选 | rclone → 云盘 |
| 自愈 | boot-agent + cron（或 while 循环） |
| 铁律 | **备份必须实测可恢复** |
