# 01 — 沙盒概览

## 这类服务是什么

在线 Jupyter 服务（如 Teradata Vantage、Google Colab、Kaggle、Paperspace、各类厂商的 Notebook 服务）本质上是：

```
厂商的 Kubernetes / Docker 集群
    ↓ 分配
一个容器实例（含 JupyterLab/Notebook）
    ↓ 你的浏览器
一个 Web 界面
```

**关键认知：你拿到的是容器，不是虚拟机。**

---

## 能拿到什么

### ✅ 硬件资源（实测）

| 资源 | 实测值 | 备注 |
|---|---|---|
| CPU | 4 × Intel Xeon @ 2.80GHz | 独占还是共享需实测 |
| 内存 | **22 GB** | 无 swap |
| 磁盘 | 135 GB overlay | 可用 27 GB（已用部分来自镜像） |
| GPU | 无 | 部分服务有 |
| 网络 | 自由出网 | 出口 IP 会变 |
| 运行时长 | 不限（只要容器不重启） | 部分服务有闲置超时 |

### ✅ 软件自由度

- **uid = 0（root）** —— 看起来是 root
- 可以 `apt-get install`（proot 内）
- 可以编译任意代码
- 可以跑任意二进制（x86-64）
- 可以自由访问外网

### ❌ 拿不到什么

| 能力 | 状态 | 原因 |
|---|---|---|
| `chroot` | ❌ | 无 `CAP_SYS_CHROOT` |
| `mount` | ❌ | 无 `CAP_SYS_ADMIN` |
| `sysctl -w` | ❌ | `/proc/sys` 只读 |
| `iptables` | ❌ | 无 `CAP_NET_ADMIN` |
| Docker | ❌ | 需要特权 |
| 内核模块 | ❌ | 需要特权 |
| `unshare`（用户命名空间） | ⚠️ | 可能被 seccomp 拦 |

## 实测环境详情

### 容器标识

```bash
$ grep -E "CapEff|CapBnd|Seccomp" /proc/self/status
CapEff:  0000000000000000        # ← 生效能力：空！
CapBnd:  00000000a80425fb        # ← 边界：有 Docker 默认集
Seccomp: 2                       # ← 已启用 seccomp
Seccomp_filters: 2
```

**`CapEff = 0` 是核心事实** —— 虽然 `uid=0`，但**一个 capability 都没有**。这就是为什么 `chroot`/`mount` 全部失败。

`CapBnd` 非零说明能力边界还在（Docker 默认集），只是没有生效。理论上可以用 `capsh` 试图提回，但通常会被 seccomp 拦住。

### 挂载结构

```
overlay /          ← 容器根，含上百层 lowerdir
/dev/root /etc/resolv.conf   ← 宿主文件 bind mount
/dev/root /etc/hostname
/dev/root /etc/hosts
/dev/root /home/jovyan/JupyterLabRoot   ← ★ 关键：宿主持久盘
shm /dev/shm  (64MB, noexec)
```

**`/home/jovyan/JupyterLabRoot` 是唯一跨容器存活的目录**。这是整个沙盒最重要的一个路径，详见 [05-持久化与迁移.md](05-持久化与迁移.md)。

### 内核

```bash
$ uname -a
Linux bf317098dea4 6.14.0-1021-gcp #22~24.04.1-Ubuntu SMP ... x86_64
```

- 内核 **6.14.0-1021-gcp** —— 是 **GCP**（Google Cloud）的定制内核
- 但容器 OS 是 **Ubuntu 20.04** —— **新内核 + 旧用户空间**

这个组合有实际影响：
- ✅ 能用新内核特性（如 io_uring 部分功能）
- ⚠️ 但 glibc 是 2.31（20.04），某些新软件要自己编

### proot 环境

```bash
$ ps aux | grep proot
1000  1520  ...  .../freeroot/usr/local/bin/proot \
  --rootfs=.../freeroot \
  -0 -w /root \
  -b /dev -b /sys -b /proc -b /etc/resolv.conf \
  --kill-on-exit
```

拆解：
| 参数 | 作用 |
|---|---|
| `--rootfs=.../freeroot` | 根目录换成 freeroot 目录（**就是仓库目录自身**） |
| `-0` | **伪装 uid/gid 为 0** |
| `-w /root` | 工作目录 `/root` |
| `-b /dev -b /sys -b /proc` | 绑定宿主这些目录（否则没有 /proc） |
| `-b /etc/resolv.conf` | 绑定 DNS 配置 |
| `--kill-on-exit` | proot 退出时杀掉所有子进程 |

### 这是 Foxytoux freeroot

[github.com/foxytouxxx/freeroot](https://github.com/foxytouxxx/freeroot) —— 很多在线 Jupyter 服务用它做“假 root”。

它的特点：
- 静态 proot 二进制（1.9 MB，含 debug_info）
- rootfs = 仓库目录自身（`--rootfs=$(pwd)`）
- 支持 x86_64 / aarch64
- 幂等：靠 `.installed` 标记避免重复安装

完整拆解见 [03-proot详解.md](03-proot详解.md#foxytoux-freeroot-的实际做法)。

## 典型的宿主机形态

这台机器的宿主是 **Jupyter 容器**，能看到的痕迹：

```
/opt/conda/bin/python3.9  /opt/conda/bin/jupyter-lab    ← Conda + JupyterLab
用户 jovyan (uid 1000)                                  ← Jupyter 标准用户
/usr/local/bin/entrypoint.sh                            ← 容器入口
/usr/local/bin/teradata-docker-start.sh                 ← 厂商启动脚本
tini -g -- ...                                          ← init 进程
```

**这是标准的 Jupyter Docker Stacks 结构。**

### 为什么会有 proot

很多 Jupyter 服务预装了 **Foxytoux freeroot**（[GitHub](https://github.com/foxytouxxx/freeroot)）——
一组脚本 + 静态 proot + Ubuntu rootfs，让用户能“像 root 一样”用 Ubuntu。
这是很多 Jupyter 服务的常见做法 —— 容器本身受限，但通过 proot 给用户一个“完整”的 Linux。

## 判断你面对的是哪种沙盒

```bash
# 1. 有没有 capability
grep CapEff /proc/self/status
#   0000000000000000  → 无特权（本文档的场景）
#   0000003fffffffff  → 完全特权（罕见，好玩）

# 2. 有没有 seccomp
grep Seccomp /proc/self/status
#   0 → 无  2 → 已启用（会拦 syscall）

# 3. 是不是 proot
ls -l /proc/1/root /                    # proot 下会有异常
ps aux | grep proot

# 4. 真实资源
nproc; free -g; df -h /

# 5. 有没有 swap
swapon --show      # 空 = 无 swap，OOM 直接杀

# 6. cgroup 限制（可能是假的）
cat /sys/fs/cgroup/memory.max 2>/dev/null
# 显示 "max" 不代表无限制！可能是外层限制，容器内看不到
```

第 6 条血泪教训：**cgroup 显示 `max` 但实际有 5 GB 硬限**的情况真实存在（宿主外层限制）。判断方法是实测 —— 分配内存并逐页写入，看什么时候被杀。

详见 `scripts/probe.sh`。

## 小结

| 维度 | 结论 |
|---|---|
| 本质 | 无特权 Docker 容器 |
| 资源 | 通常很大方（GB 级内存、几十 GB 磁盘） |
| 权限 | uid=0 但 CapEff=0，**chroot/mount 全废** |
| 解法 | **proot** —— 用 ptrace 模拟，绕过 capability 限制 |
| 持久化 | 只有宿主持久盘那个目录靠谱 |
| 风险 | 容器重启全丢；ToS 上有封号风险 |
