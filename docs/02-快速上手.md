# 02 — 快速上手

从拿到账号到跑起第一个任务的完整流程。

---

## Step 0：先摸清底细

**别急着装东西，先探测。** 否则你会花两小时装好环境，然后发现内存只有 1 GB。

```bash
# 一键探测
bash scripts/probe.sh
```

手动版：

```bash
echo "=== OS / 内核 ==="
cat /etc/os-release | head -2; uname -r
echo "=== CPU ==="; nproc
echo "=== 内存 ==="; free -g
echo "=== 磁盘 ==="; df -h /
echo "=== 权限 ==="; id; grep CapEff /proc/self/status
echo "=== seccomp ==="; grep Seccomp /proc/self/status
echo "=== swap ==="; swapon --show
echo "=== cgroup ==="; cat /sys/fs/cgroup/memory.max 2>/dev/null
echo "=== 网络 ==="; curl -s --max-time 8 https://api.ipify.org
```

### 关键判断

| 现象 | 含义 |
|---|---|
| `CapEff: 0000000000000000` | 无特权 → **必须用 proot** |
| `Seccomp: 2` | seccomp 启用 → 某些 syscall 会 `EPERM` |
| `swapon` 为空 | 无 swap → **OOM 直接 SIGKILL，没有缓冲** |
| cgroup 显示 `max` | ⚠️ **不可信**，可能是外层限制 |

## Step 1：Jupyter 界面里能做什么

### 基础操作

```python
# 在 Notebook 里执行 shell
!ls -la
!nproc

# 长时间命令（用 &
!nohup long_task.sh > /tmp/out.log 2>&1 &

# 看输出
!tail -f /tmp/out.log
```

### ⚠️ Notebook 执行 shell 的坑

1. **`!` 命令会阻塞单元格** —— 长任务用 `nohup ... &` 后台跑
2. **Notebook 内核重启 = 所有变量丢失**
3. **浏览器关闭后，后台进程通常继续跑**（但部分服务会杀）

### 用 Jupyter 的 Terminal 更好

JupyterLab 有内置 Terminal（`File → New → Terminal`），比 Notebook 的 `!` 好用得多：
- 真正的交互式 shell
- 支持 `vim`/`tmux`
- 长任务不受单元格生命周期影响

**强烈推荐用 Terminal 而不是 Notebook cell 跑系统操作。**

## Step 2：装 proot 环境（如果需要 root 能力）

如果 `CapEff=0`，`apt-get install` 在容器根里可能失败。用 proot 拿到一个完整发行版：

### ✅ 首选：Foxytoux freeroot

```bash
# 一行命令搞定
git clone https://github.com/foxytouxxx/freeroot.git
cd freeroot
bash root.sh
```

它做了三件事：
1. 下载静态 proot 到 `usr/local/bin/proot`（1.9 MB）
2. 下载 Ubuntu 20.04 base rootfs 解到**当前目录**
3. 用这个 proot 把自己拉起来

进去后提示符变成 `root@host:/#`，`apt-get` 就能用了。

**验证**：
```bash
cat /etc/os-release      # 应该显示 Ubuntu 20.04 而不是宿主的系统
apt-get update           # 能正常工作就对了
```

> **`--rootfs=$(pwd)`** 意味着 `freeroot/` 目录就是 guest 的 `/`。
> 不要把它当普通目录删改。详情见 [03-proot详解.md](03-proot详解.md#foxytoux-freeroot-的实际做法)。

### 备选 A：服务方预装了 freeroot

```bash
# 找找有没有现成的
ls /home/jovyan/*/freeroot 2>/dev/null
find / -maxdepth 5 -name "root.sh" -path "*freeroot*" 2>/dev/null
```

很多 Jupyter 沙盒已经预装，直接在 Tmux/Terminal 里跑它的 `root.sh` 即可。

### 备选 B：自己搭

```bash
bash scripts/bootstrap.sh
```

会下载 rootfs + proot，并额外配置 `policy-rc.d`、apt 源、常用工具。

## Step 3：初始化环境

进入 proot 后（提示符变成 `root@xxx:/#` 的那种感觉）：

```bash
# 换源（Ubuntu 20.04）
cat > /etc/apt/sources.list <<'EOF'
deb http://archive.ubuntu.com/ubuntu focal main restricted universe multiverse
deb http://archive.ubuntu.com/ubuntu focal-updates main restricted universe multiverse
deb http://archive.ubuntu.com/ubuntu focal-security main restricted universe multiverse
EOF

apt-get update
apt-get install -y --no-install-recommends \
  ca-certificates curl wget git vim build-essential \
  python3 python3-pip p7zip-full unzip less htop

# 修 DNS（如果 apt 报域名解析失败）
echo "nameserver 8.8.8.8" > /etc/resolv.conf
```

### ⚠️ proot 下 apt 的坑

| 问题 | 原因 | 解决 |
|---|---|---|
| `Could not resolve` | `/etc/resolv.conf` 没绑定 | `-b /etc/resolv.conf` |
| `dpkg: error: unable to...` | 某些包要改 `/proc` | 通常无害，可忽略 |
| `postinst` 卡住 | 服务启动失败（无 systemd） | 用 `--no-install-recommends`，或 `policy-rc.d` |
| `Operation not permitted` | setuid / chroot | 见下 |

**禁用服务自启**（proot 里没有 systemd）：

```bash
cat > /usr/sbin/policy-rc.d <<'EOF'
#!/bin/sh
exit 101
EOF
chmod +x /usr/sbin/policy-rc.d
```

这样 `apt` 装包时不会试图启动服务（proot 里启动不了）。

## Step 4：跑你的第一个任务

### 测试 CPU

```bash
# 4 核满跑
for i in $(seq 4); do
  ( while :; do :; done ) &
done
sleep 10
kill %1 %2 %3 %4

# 看实际频率/温度（可能不可用）
cat /proc/cpuinfo | grep MHz | head -4
```

### 测试内存上限（重要！）

```bash
# 逐页写入，看什么时候被杀
python3 - <<'EOF'
import os
chunk = b'x' * (1024*1024*100)   # 100MB
buf = []
for i in range(1, 200):
    buf.append(bytearray(chunk))   # 逐页触发真实分配
    print(f"{i*100} MB", flush=True)
EOF
# 如果在某个值突然 "Killed" → 那就是真实上限
```

这个测试能揭穿 cgroup 的谎言。见 `scripts/probe.sh`。

### 跑长任务

```bash
# 用 nohup + & 后台跑，日志重定向
nohup ./my_long_task > /tmp/task.log 2>&1 &
echo "PID: $!"

# 看进度
tail -f /tmp/task.log

# 保活（防止父 shell 退出带走进程）
setsid nohup ./task > /tmp/task.log 2>&1 &
```

**用 `setsid` 比 `nohup` 更可靠** —— 它创建一个新会话，彻底脱离终端。

## Step 5：暴露服务（如果需要）

沙盒里的 Web 服务默认外界访问不到。几种方式：

### 方式 A：Jupyter 代理

```
https://<jupyter-host>/user/<user>/proxy/<port>/
```

前提是服务方启用了 `jupyter-server-proxy`。

### 方式 B：SSH 反向隧道

如果你有一台有公网 IP 的机器：

```bash
# 在沙盒里
ssh -R 18080:localhost:8080 user@your-server

# 在 your-server 上访问
curl http://localhost:18080
```

### 方式 C：frp / ngrok / cloudflared

```bash
# cloudflared（最省事）
curl -L -o cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x cloudflared
./cloudflared tunnel --url http://localhost:8080
# 会给你一个 *.trycloudflare.com 的临时地址
```

详见 [04-资源利用.md](04-资源利用.md) 的网络部分。

## 常见问题

### Q: `apt-get install` 报 `Operation not permitted`

**A**: 你在容器根里，不在 proot 里。要么用 proot，要么检查具体是哪个包在调特权 syscall。

### Q: proot 里 `ps aux` 只看到自己

**A**: 正常。proot 不做 PID 隔离，`/proc` 是宿主的，但你只看到自己的进程树。

### Q: 编译时 `gcc: internal compiler error` 或莫名 OOM

**A**: 内存不足。无 swap 直接 SIGKILL。先做内存实测，再用 `-j` 限制并行度。

### Q: 后台任务跑一会儿就没了

**A**: 
1. 用 `setsid nohup` 而非裸 `&`
2. 容器闲置超时会杀（如果有）
3. 检查 `dmesg | tail` 看是否 OOM

### Q: 磁盘满了

**A**: 
```bash
du -sh /var/cache/apt /tmp /root/.cache 2>/dev/null
apt-get clean
rm -rf /tmp/*
```
编译产物占空间最大 —— `go build` 的 cache 能吃掉几个 GB。
